# Repository Guide

This guide describes how to work with the project folders and generated outputs.

## Running a Project

Open the project folder first, install dependencies, then run the documented commands:

```bash
cd projects/01_housing_price_prediction
pip install -r requirements.txt
python src/train.py
python src/predict.py --sample-index 0
```

Running from the project folder keeps relative paths simple and ensures outputs are written to that project's own `artifacts/` directory.

## Generated Artifacts

Most projects create an `artifacts/` folder after running. Typical files include:

- `.joblib` model bundles
- `.json` training or evaluation reports
- `.csv` forecast files
- annotated image outputs

These files are runtime outputs. They can be regenerated by rerunning the scripts.

## Data

Some projects include CSV files in `sample_data/`. Other projects generate demo data automatically from scripts such as:

```bash
python src/generate_demo_images.py
python src/export_demo_images.py
python src/generate_demo_data.py
```

## Documentation Standard

Every project README should include:

- what the project does
- what is included
- setup and run commands
- generated outputs
- the visible outcome of the project

## Adding a New Project

Use the existing numbered structure:

```text
11_new_project_name/
|-- README.md
|-- requirements.txt
|-- sample_data/
|-- src/
```

Keep commands runnable from inside the project folder and write generated files into `artifacts/`.
